Release notes

Every published version of the Open24 platform — combined frontend and backend. Each card is a self-contained summary of what changed and when. Copy a version link to share or to filter the page to just that release.

Showing v— only
v1.2.0 June 16, 2026

Admin course management

  • Delete a course safely. Courses can now be deleted as soon as they have no active enrollments — old sessions, payments, waitinglist entries and reserved court slots are cleaned up automatically as a single transaction.
  • Clearer "can't delete" feedback. When a course can't be removed, the Delete button stays visible but disabled with an amber info icon. Hovering reveals a panel explaining exactly why (e.g. "This course has 3 active enrollments").
  • All Sessions view toggle. The session list now offers a Cards view (default) and a Table view for quick scanning. Your preference is remembered per browser.

Course checkout

  • Header navigation fixed on the checkout page. Clicking the Course link in the top navigation while on /enrollments/checkout previously sent customers to a broken /enrollments/enroll URL. It now reliably returns to the main /enroll browse page from anywhere in the app, so customers can step back out of checkout to keep shopping for courses without losing the navigation.
v1.1.7 June 14, 2026

Admin "Create User" overhaul

  • Admins no longer set passwords or activation flags. The form now collects just the basics (name, email, phone, optional Stripe ID); the new user is emailed an invitation link to sign agreements and set their own password.
  • The success toast now tells the admin whether the invitation email was actually delivered, so they know if a manual resend is needed.

Invitation email redesigned

  • Polished new layout — centered hero, personalised greeting (with a graceful "Hi there," fallback), clear "What to expect" steps, prominent CTA and a 7-day-validity reassurance.

Bug fixes

  • Admin-created users no longer end up with blank first/last names.
  • Stray template tokens (e.g. {{/if}}) no longer leak into email bodies.
v1.1.6 June 13, 2026

Semi-private on-demand lessons

  • The 2nd student on a semi-private private-lesson booking is now shown inline on the coach calendar — both on the event block and in the floating tooltip — without widening the cell.
  • Editing an existing booking correctly re-loads the 2nd student, and removing them now sticks (no more "ghost" reappearance on the next edit).

On-demand requests

  • "Booked by Coach" badges now also recognise legacy admin-direct enrollments, not just newer head-coach bookings.
v1.1.3 June 12, 2026

Head-coach booking flow

  • For semi-private private lessons, head coaches can now enrol a second student in the same booking via a tidy "+ Add 2nd student" affordance that only appears when relevant.

Admin on-demand requests page

  • Each row now shows whether the request originated from a customer (sky "Self-serve" pill) or a coach (violet "Booked by Coach" pill).
  • The Coach column now falls back to the scheduled session's coach when the course doesn't have one assigned yet.
v1.1.1 June 11, 2026

Coach calendar polish

  • Course event tooltips are now colour-coded by cohort and on-demand semi-private lessons get their own distinct orange palette for at-a-glance differentiation.
  • Course-name links inside event blocks open in a new tab so the coach doesn't lose calendar context.

Pending on-demand requests indicator

  • The sidebar "On-Demand Requests" menu item now shows a red badge with the count of pending requests, refreshed automatically after each action.

Enrollments & transactions

  • The enrollment detail's progress chip now counts implied attendance into the single "Attended" total — coaches no longer see a confusing split.
  • Head-coach offline bookings on the Transactions page now correctly show "Offline" instead of an empty dash.
v1.1.0 June 10, 2026

Private-lesson confirmation emails

  • Customers and coaches now receive a polished "Your Private Lesson Is Scheduled" email when an on-demand request is booked — and a "Rescheduled" variant if the time changes later.

Head-coach booking modal

  • The selected-student card now offers quick Call, Text and Email buttons so coaches can reach out without leaving the booking flow.

Coach calendar

  • The "9 AM – 8 PM / Full Day" time-range toggle is now a prominent, animated control surfaced inline on the page header.

Admin polish

  • Session attendance details now show human-readable enrolment types (e.g. "Enrolled by Head Coach") instead of raw codes.
  • Cancellation timestamps in admin emails now render in a friendly timezone-aware format (e.g. Wed, Jun 10, 2026, 9:34 PM EDT).
v1.0.0 June 8, 2026

First stable release

  • Head Coach role — Head Coaches now have full course-management parity with Admins (courses, cohorts, enrollments, sessions, attendances, waitlists, on-demand requests) plus a dedicated sidebar group and a new read-only Resource Calendar page polished to match the admin view.
  • New enrolments by a head coach are tagged as Enrolled by Head Coach end-to-end, distinct from admin enrolments.
  • Stripe checkout hardening — invalid session_id values are rejected up-front, stopping bot/prefetch noise hitting Stripe with placeholder URLs.
  • The wallet now labels migrated gift-card credits as From: System Migration instead of Unknown.
v0.7 – v0.9 March – May 2026

Pre-1.0 highlights

  • Initial public release of court booking, course enrollment (fixed, ongoing and on-demand), waiting list, refunds & store credits, gift cards and passes, membership subscriptions, and the admin/coach dashboards.
  • Membership migration tooling — bulk import of legacy customers, gift cards and passes from the previous system with email-driven reactivation.
  • Lifecycle email framework with database-managed templates (registration, confirmation, cancellation, refund, waiver, etc.).
  • Stripe payment integration (cards, store credits, subscriptions) and a unified Transactions page.
  • Resource calendar with conflict detection, recurring courses, pricing rules and cohort-aware visuals.

The full per-version pre-1.0 history is preserved in the platform repository changelogs.
